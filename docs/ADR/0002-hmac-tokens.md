# ADR-0002: HMAC-SHA256 для токенов вместо argon2/bcrypt

Статус: принято · Дата: 2026-08-12

## Контекст

ТЗ предлагает хранить host-токен как argon2/bcrypt-хеш. Медленные KDF
существуют для защиты низкоэнтропийных паролей от перебора.

## Решение

Токены (host и participant) — 256 бит криптостойкой случайности
(`crypto.randomBytes(32)`). Для равномерно случайного 256-битного входа
перебор невозможен независимо от скорости хеша, поэтому храним
HMAC-SHA256(pepper, token); сравнение — `timingSafeEqual`.

## Последствия

- Нет нативных зависимостей (argon2/bcrypt) — проще Docker и Windows-дев.
- Нет ~50–200 мс KDF-латентности на каждую проверку токена (а проверка
  происходит на каждой мутации и каждом узнавании участника).
- Pepper (`TOKEN_PEPPER`) обязателен и не подлежит смене без инвалидации
  всех токенов — задокументировано в README и .env.example.
