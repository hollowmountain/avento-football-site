# ADR-0003: SSE через in-process шину по умолчанию, Redis pub/sub — опция

Статус: принято · Дата: 2026-08-12

## Контекст

ТЗ упоминает Redis pub/sub для SSE. Продакшен — Railway с одним инстансом
(вертикальное масштабирование); события нужны только подписчикам того же
процесса, который принял мутацию.

## Решение

Порт `EventBus` с двумя адаптерами:

- **in-process `EventEmitter`** — по умолчанию (без REDIS_URL);
- **Redis pub/sub** — включается автоматически при `REDIS_URL`
  (обязателен при >1 реплики, иначе события видят не все).

Доставка — «notify-then-fetch»: события тонкие, клиент по любому событию
перезапрашивает состояние игры (инвалидация TanStack Query). Это снимает
проблемы Last-Event-ID/replay: после реконнекта первый refetch даёт
актуальное состояние.

## Последствия

- Локальная разработка и single-instance прод не требуют Redis вовсе.
- Переход на горизонтальное масштабирование = задать REDIS_URL.
- SSE-роут: nodejs runtime, `Cache-Control: no-cache, no-transform`,
  ping-комментарий каждые 25 с, отписка по `request.signal` abort.
