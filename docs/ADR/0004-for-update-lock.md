# ADR-0004: SELECT FOR UPDATE вместо Serializable + retry

Статус: принято · Дата: 2026-08-12

## Контекст

ТЗ допускает оба пути защиты от гонки на последнее место: транзакции
уровня Serializable или явную блокировку строки.

## Решение

Пессимистичная блокировка: `SELECT id FROM "Game" WHERE code = $1 FOR UPDATE`
в начале interactive-транзакции (`PrismaUnitOfWork.withGameLock`). Все
мутации состава одной игры сериализуются на этом локе.

Почему не Serializable: под конкуренцией Prisma кидает P2034 и требует
retry-обвязку; при 10 одновременных запросах ретраи каскадятся и возможно
голодание. FOR UPDATE даёт детерминированную очередь без ретраев, код
проще и тестируемее.

## Последствия

- Инвариант `MAIN ≤ maxPlayers` держится под любой конкуренцией —
  подтверждено тестом гонки (10 параллельных join, пул соединений 20).
- Пропускная способность мутаций одной игры ограничена локом — для
  «сбора на футбол» это заведомо не узкое место.
