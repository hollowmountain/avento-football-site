Прочитай `docs/HANDOFF-QUICK-GAME.md`, `AGENTS.md` и `docs/ARCHITECTURE.md`,
затем построй режим «Быстрая игра» в проекте AVENTO ASCENT.

## Контекст проекта (всё уже готово и работает)

- **AVENTO ASCENT** — сайт сбора на любительский футбол: Next.js 16 (App
  Router), React 19, Prisma 7 + PostgreSQL, Tailwind 4 + shadcn. Все проверки
  зелёные: `npm run lint && npm run typecheck && npm run test`, e2e —
  `npm run build && npm run e2e`.
- **Локальная среда (Windows, без Docker и глобального Node!):**
  - портативный Node в `.tools\node` — в КАЖДОЙ PowerShell-команде сначала
    `$env:Path = "C:\Users\User\Desktop\footsite\.tools\node;" + $env:Path`;
  - портативный PostgreSQL на порту **5433**: `npm run db:start` / `db:stop`;
  - dev: `npm run dev`; прод: `npm run build; npm run start` (порт 3000).
- **Дизайн «Табло»** (утверждён): янтарь `#FFB020` на чернильном `#0D1013`,
  тёмная тема по умолчанию. Ровно ДВА шрифта: заголовки/кнопки/цифры —
  `.display` (Sofia Sans Extra Condensed), текст — Sofia Sans. Классы-помощники
  в `globals.css`: `.display`, `.eyebrow`, `.digits`; компоненты — `Pill`
  (`src/shared/ui/pill.tsx`), Card/Button/Input/Dialog из `src/shared/ui`.
  Янтарная ЗАЛИВКА — только у главного действия; статусы — контуром.
  В светлой теме янтарь-как-текст — токен `text-lamp` (не `text-primary`!).
- **Грабли, которые уже съедены** (не наступать):
  - имя цветового токена Tailwind не должно начинаться с имени встроенной
    палитры (`--color-amber-ink` → `bg-amber-ink` молча не компилировался);
  - реакт-хуки линт строгий: нельзя `Date.now()`/чтение localStorage в
    рендере (только lazy `useState(() => ...)` или обработчики), нельзя
    `setState` синхронно в effect (для «после гидратации» —
    `useSyncExternalStore`, пример: `src/shared/hooks/use-host-token.ts`);
  - все строки UI — через next-intl (`messages/ru.json` + `en.json`);
  - скриншоты для проверки снимать Playwright-скриптом
    (chromium уже установлен), встроенная панель браузера скриншоты не отдаёт.

## Что построить

### 1. Вкладка в шапке

В `src/shared/ui/site-header.tsx` после «Создать игру» — пункт
**«Быстрая игра»** → `/quick`. На мобильном пункт «Игры» можно скрыть
(логотип и так ведёт на ленту).

### 2. `/quick` — работающий режим матч-дня (клиентский, без бэкенда)

Файлы: `src/app/(public)/quick/page.tsx` + модуль `src/modules/quick/`
(domain/presentation по слоям, границы стережёт eslint-plugin-boundaries).
Всё состояние — в localStorage (`avento_quick_day_v1`), никаких изменений
схемы БД. Гидратация через useSyncExternalStore-паттерн.

Экран без начатого дня: заголовок, 1–2 строки описания, кнопка
**«Начать игровой день»** и под ней ссылка **«Посмотреть, как работает»**
→ `/quick/demo`.

Поток (ровно по 10 пунктам заказчика):

1. **Кто пришёл**: добавление игроков по имени + кнопка «Гость» (гость — тот
   же игрок с пометкой). Все пришедшие распределяются по командам;
   нажатие на игрока переводит его в следующую команду.
2. **Составы**: 2 или 3 команды (третья — ожидающая). Карандаш в заголовке
   команды: переименовать и сменить цвет (палитра 5–6 пресетов, читаемых
   на чернильном фоне).
3. **Начать матч**: выбрать, кто играет первым; ожидающий состав выходит
   на замену автоматически.
4. **Матч**: таймер (старт/пауза), большой счёт; нажатие на счёт команды =
   гол → открывается окно **«Кто забил?»**: автор гола и ассистент
   (по желанию, можно «без автора»). Отмена последнего гола.
5. **Завершение**: подтвердить результат. **Победитель остаётся на поле**,
   проигравший — в конец очереди, ожидающая команда выходит. При ничьей —
   уходит команда, дольше находящаяся на поле (написать правило в UI).
6. **Таблица дня**: победа +3, ничья +1, поражение 0; В/Н/П, забитые,
   пропущенные, разница. Сортировка: очки → разница → забитые.
7. **Журнал дня**: каждый матч сохранён, счёт можно исправить
   (плюс/минус по каждой стороне), день целиком сохраняется в localStorage.
8. **Публикация**: «Поделиться итогами» — текст со списком матчей и таблицей
   через navigator.share/clipboard + **карточка результата** (canvas
   1080×1350, чернильный фон, янтарные акценты, названия команд в их
   цветах) — share файлом или скачивание PNG. Ссылку на веб-страницу
   результата не делать (нужен бэкенд) — только текст и карточка.

Чистую логику вынести в `src/modules/quick/domain/` с юнит-тестами:
`standings.ts` (расчёт таблицы) и `rotation.ts` (очередь после матча,
включая правило ничьей) — тесты в `tests/unit/`.

### 3. `/quick/demo` — страница-пример «как работает»

Обучающий тур на 10 шагов (формулировки выше — сохранить смысл дословно).
Требование заказчика к виду: **объяснение яркое, фон за ним чуть темнее**,
чтобы внимание было на тексте. Реализация: на каждом шаге — статичная
сцена-иллюстрация (мини-мок соответствующего экрана в стиле «Табло»),
поверх — затемняющая вуаль `bg-background/70`, над ней яркая карточка
с номером шага, заголовком и текстом. Кнопки **«Далее»** и
**«Пропустить»** (пропустить = сразу на `/quick`); на последнем шаге —
**«Начать игровой день»**. Прогресс «3 / 10». Уважать
prefers-reduced-motion; всё через i18n.

## Проверка (обязательно)

1. `npm run lint && npm run typecheck && npm run test` — зелёные.
2. `npm run build`, потом `npx playwright test` — 2 существующих e2e зелёные.
3. Прогнать руками через Playwright-скрипт: полный цикл быстрой игры
   (3 команды, 2 матча, голы с авторами, исправление счёта, таблица) +
   скриншоты мобильные (390px) и десктопные, тёмная и светлая темы,
   `/quick/demo` пройти по шагам. Пришли скриншоты пользователю.
4. Закоммитить (Conventional Commits, тексты на русском, trailer
   `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`).
